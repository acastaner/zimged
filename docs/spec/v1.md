# zimged v1 specification

zimged is a small, very fast image viewer and quick editor. You double-click an image and it is on screen almost at once. The wheel or the arrow keys move through the other images in the same folder. You can mark an image up the way Greenshot's Image Editor does (shapes, text, numbered steps, highlights, blur), then save or copy it. It is not a full image editor.

This spec is the destination of the [zimged v1 spec](https://github.com/acastaner/zimged/issues/1) map. Each section links the ticket that decided it; the tickets hold the reasoning. Domain terms (**Image**, **Annotation**, **Inset**, **Step counter**, **Flatten**, **Image operation**, **History**, **Sibling**) are defined in [GLOSSARY.md](../../GLOSSARY.md). Architecture decisions are in [docs/adr](../adr).

---

## 1. Platforms and performance

### 1.1 Platforms

- **Linux is first-class:** native Wayland and X11 from one binary. Builds are x86-64 first; aarch64 if it's cheap.
- **Windows 10+ and macOS (arm64 and x64)** are supported on a best-effort basis: they're built and released, but no performance budget applies ([Lock the stack](https://github.com/acastaner/zimged/issues/10), [ADR 0002](../adr/0002-rust-egui-glow-linux-first.md)).

### 1.2 Budgets (hard, Linux)

All budgets are measured on Linux with the **balanced** (default) power profile, on a mid-range desktop. The reference machine is an i5-12600KF.

| Budget | Target | How it's measured |
|---|---|---|
| Cold start | **p90 ≤ 150 ms** from launch to the first image painted, for a 12 MP JPEG | `tools/bench`: 15 launches, each after 1.5 s idle, on Wayland |
| Next/previous Sibling | **p90 ≤ 50 ms** from key press to paint, when flipping every 200 ms | `tools/bench`, 25 switches |
| Large directories | Opening an image in a folder of 10,000 files paints the first image no later than in a folder of one | `tools/bench`, with a generated 10,000-file folder |
| Memory while viewing | Display-size cache ≤ 256 MB; full resolution only for the Image being edited | inspection |

- Holding the arrow key down is not budgeted; it is decode-bound by nature.
- The Flatpak build isn't budgeted: its sandbox adds launch overhead.

The [cold-start spike](https://github.com/acastaner/zimged/issues/9) measured these numbers with this stack's design: p90 122 ms cold start, and about 5–12 ms per Sibling switch. The spike branch `prototype/startup-spike` holds the benchmark that `tools/bench` descends from.

### 1.3 The startup path

The budget depends on this ordering, so treat it as a requirement:

1. `main()` immediately starts two threads. The **first-image decode** reads the path from the command line and decodes it at display size (§5.2). The **config read** loads `config.toml`.
2. Only when *Allow multiple instances* is off: try the single-instance socket (§8.4). If another instance answers, hand it the path and exit.
3. Create the window and the OpenGL context (eframe + glow). This runs in parallel with the decode.
4. Paint the first frame with the image as soon as both have finished.
5. Only **after** the first image is painted: scan the directory, start the directory watcher, start prefetching, load fonts for the UI chrome where they aren't already loaded, and initialise Skia (lazily, on the first Annotation).

Nothing else may land on the path from `main()` to the first paint. In particular: no directory scan, no Skia, no font enumeration, no MIME database lookup. Every new dependency that runs before the first paint has to be checked against the budget with `tools/bench`.

## 2. Window and layout

Decided in [UI layout mockup](https://github.com/acastaner/zimged/issues/8), "variant A" of the prototype on branch `prototype/ui-layout`. It's a single window: the tools are always available, and there is no separate viewing mode.

```
┌──────────────────────────────────────────────────────────────┐
│ File  Edit  Image  View  Help              [💾][⤓][⧉][↶][⟳][🗑]│  menu bar + quick actions
├──────────────────────────────────────────────────────────────┤
│ Line ■  Fill ■ ∅  Thickness [3]  ☑ Shadow                     │  property bar (active tool)
├────┬─────────────────────────────────────────────────────────┤
│ ⬚  │                                                         │
│ ▭  │                                                         │
│ ◯  │                                                         │
│ ╱  │                     canvas                              │
│ ➚  │             (Image, fit to window)                      │
│ ✎  │                                                         │
│ T  │                                                         │
│ ①  │                                                         │
│ ▨  │                                                         │
│ ▦  │                                                         │
│ ⌗  │                                                         │
├────┴─────────────────────────────────────────────────────────┤
│ IMG_0412.jpg •   3 / 42   4000×3000   Fit   ▶ animated   <msg>│  status bar
└──────────────────────────────────────────────────────────────┘
```

- **Menu bar:** File, Edit, Image, View, Help. On its right are quick actions: save, save as, copy, undo, the Image menu (rotate, flip, resize) and trash.
- **Property bar:** only the active tool's controls (§4.3).
  - With the select tool and Annotations selected: their style controls, plus Delete, Bring to front and Send to back.
  - With crop: the crop size, **Apply (Enter)** and **Cancel (Esc)**.
  - Otherwise, a short hint.
- **Tool strip:** a vertical strip on the left, in the order of §4.1.
- **Status bar, left to right:**
  - the file name, with ` •` when there are unsaved changes;
  - the Sibling position `n / N`;
  - the pixel size;
  - the zoom (`Fit` or a percentage);
  - the animation state (`▶ animated` or `⏸ frozen at frame 1`), when there is one;
  - a transient message slot. Messages include "First image in folder", "Last image in folder", "Image copied to the clipboard", "Annotations copied to the clipboard", "Moved to trash" and "View only: image too large to edit".
- **Selected Annotations:** a dashed bounding box with 8 handles.
- **F11:** fullscreen, which hides the menu, property bar, tool strip and status bar.
- **Dialogs** are modal (§6.4).
- **Empty window:** started with no file, the canvas shows "Open (Ctrl+O), drop or paste (Ctrl+V) an image".
- **Window size and maximised state** are remembered (§8.3). Every new Image opens fit to the window.

## 3. Viewer

### 3.1 Navigation

| Input | Action |
|---|---|
| Wheel / scroll (at Fit) | Down / up: next / previous Sibling |
| Wheel / scroll (zoomed past Fit) | Pan the Image (both axes); does not navigate |
| → / ← | Next / previous Sibling (always, zoomed or not) |
| Ctrl+wheel, `+` / `-` | Zoom around the cursor (keys: around the centre) |
| `0` | Fit to window (the default for every new Image) |
| F11 | Fullscreen |
| Delete (no Annotation selected) | Move the file to the system trash, then show the next Sibling (or the previous one, at the end of the list) |

- **Scroll switches on zoom state:** while the Image is zoomed past Fit (larger than the canvas), a plain scroll pans it, following the platform's natural-scroll direction so the content tracks the gesture; a notched mouse wheel pans too. At Fit (or wherever the Image is not larger than the canvas), a scroll navigates Siblings as above. The arrow keys always navigate Siblings, so navigation is never lost while panning with scroll. Space+drag, middle-drag and Shift+wheel also pan (§7.2). Decided in [Scroll-to-pan a zoomed Image](https://github.com/acastaner/zimged/issues/50), [ADR 0005](../adr/0005-scroll-to-pan-a-zoomed-image.md).
- **At the ends of the list:** there is no wrap-around. At the first or last image, the view stays put and the status bar shows "First image in folder" or "Last image in folder".
- **Unsaved changes:** moving to a Sibling with unsaved changes opens the Save / Discard / Cancel dialog (§6.4).

### 3.2 Siblings

Siblings are the files in the Image's directory with a supported extension (§5.1), matched case-insensitively. Hidden files are excluded. Decided in [OS-native filename ordering](https://github.com/acastaner/zimged/issues/6).

**Order:** the file manager's own order, reproduced exactly, quirks included.

| Platform | Ordering |
|---|---|
| Windows | `StrCmpLogicalW` (via the `windows` crate). If the `NoStrCmpLogical` policy is set, ordinal comparison instead, as Explorer does |
| macOS | `NSString localizedStandardCompare:` (via `objc2-foundation`) |
| Linux, `XDG_CURRENT_DESKTOP` contains `KDE` (split on `:`) | A Rust port of Dolphin's `KFileItemModel` comparison (ICU-numeric, case-insensitive; base name before extension; the 26.08 decimal rule) |
| Linux, anything else | A Rust port of GLib's `g_utf8_collate_key_for_filename`, compared with `strcmp`. Names starting with `.` or `#` sort last. This includes the `IMG3`-after-`img10` quirk |

**Scanning and watching:**
- The directory is scanned after the first paint (§1.3). Until the scan completes, the status bar shows `? / ?`.
- The `notify` crate watches the directory. New, deleted and renamed files update the Sibling list live, and the current Image keeps its place in it.
- If the current file is deleted from outside zimged, the Image stays open and is treated as unsaved.

### 3.3 Prefetch and cache

- **What's kept:** display-size decodes of the **next two Siblings in the direction of travel and one behind**. The direction is the last move; it's forward at startup.
- **Decode pool:** `min(4, cores ÷ 2)` threads, at least 1. Decodes that fall outside the window are cancelled before they start, and their results are dropped if they've already finished.
- **Cache cap:** about 256 MB of display-size pixels. Least-recently-shown entries are evicted first, and the current Image is never evicted.
- **Not cached yet:** if the target of a move isn't cached, it's decoded at the highest priority and shown as soon as it's ready. The previous image stays on screen until then.

### 3.4 Animation

- Animated GIF and WebP play in the viewer, frames composited by the decoder.
- The first Annotation or Image operation freezes the animation on frame 1. The status bar shows `⏸ frozen at frame 1` and the message "Animation frozen at frame 1 for editing".
- Saving an edited animation over its own file needs confirmation (§6.4). The saved file is a still image.

### 3.5 Starting zimged

- **With a path argument:** open that file.
- **Without one:** the empty window (§2).
- **In the empty window:** Ctrl+V makes the clipboard image *the* Image, titled "Clipboard image".
  - It has no Siblings until it's saved.
  - Ctrl+S on it acts as Save As.
  - If the clipboard holds no image, the status bar says so.
- **Ctrl+O:** the native open dialog (`rfd`), with the unsaved-changes prompt if needed.
- **Dropping a file onto the window:** opens it as the new Image, with the unsaved-changes prompt if needed. **Ctrl+drop** inserts it as an Inset instead (§4.6).

## 4. Editor

Decided in [Annotation and undo semantics](https://github.com/acastaner/zimged/issues/7) and [ADR 0001](../adr/0001-annotations-survive-image-operations.md).

### 4.1 Tools

The order and the single-key shortcuts follow Greenshot.

| Key | Tool | Behaviour |
|---|---|---|
| Esc | Select | Click to select, Shift+click to add to the selection, drag on empty space for a rubber-band selection. Drag moves the selection; handles resize it. Double-click on text edits it |
| R | Rectangle | Drag. Shift makes a square |
| E | Ellipse | Drag. Shift makes a circle |
| L | Line | Drag. Shift snaps to 15° steps |
| A | Arrow | Drag. Shift snaps to 15° steps. Arrowheads: end (default), start, both or none |
| F | Freehand | Drag. The stroke is lightly smoothed |
| T | Text | Click places a box and **starts editing immediately** (§4.4) |
| I | Step counter | Click places the next number (§4.5) |
| H | Highlight | Drag a region. Modes: text (default), area, grayscale, magnify |
| O | Obfuscate | Drag a region. Modes: pixelate (default), blur |
| C | Crop | Drag a region, adjust it with the handles. Enter applies, Esc cancels. This is an Image operation (§4.7) |

**After drawing:**
- The tool stays active, so you can draw several shapes in a row.
- The new Annotation is selected, so the property bar edits it.
- Esc returns to the select tool. Esc while editing text first finishes the text.

### 4.2 Annotation behaviour

- **Stacking:** new Annotations go on top. Bring to front and Send to back are in the property bar; Ctrl+] and Ctrl+[ move one level up or down.
- **Highlight and obfuscate are live:** they act on **everything below them in z-order**, the Image and lower Annotations alike. They recompute whenever they move or resize, or when anything under them changes. What's on screen is exactly what gets Flattened.
  - **Text highlight:** a translucent colour multiplied over the region.
  - **Area highlight:** everything outside the region is dimmed.
  - **Grayscale highlight:** everything outside the region is shown in grayscale.
  - **Magnify:** the region shows what's under it, enlarged by a factor (default 2×, adjustable).
  - **Pixelate:** blocks whose size is the strength setting.
  - **Blur:** a Gaussian blur whose radius is the strength setting.
- **Several Annotations at once:** a multi-selection can be moved, deleted and restyled together. **Ctrl+D** duplicates the selection, offset by 10 px, without touching the clipboard.
- **Delete** removes the selected Annotations. With nothing selected, it trashes the file (§3.1).

### 4.3 Style properties

| Tool | Property bar controls |
|---|---|
| Rectangle, ellipse | Line colour, fill colour (or none), thickness, shadow |
| Line, freehand | Line colour, thickness, shadow |
| Arrow | Line colour, thickness, arrowheads, shadow |
| Text | Font, size, text colour, fill colour (or none), shadow |
| Step counter | Fill colour, size, shadow |
| Highlight | Mode, colour (text mode), magnification (magnify mode) |
| Obfuscate | Mode, strength |
| Inset | Shadow, border (none or a colour and thickness) |

Changing a property while Annotations are selected restyles them **and** becomes that tool's default. Defaults persist between runs (§8.3).

### 4.4 Text

- **Placing:** a click places a box sized to the font's line height and wide enough for 4–5 characters, and puts it in editing mode straight away.
- **Typing:** the box grows as you type. Enter adds a line.
- **Finishing:** Esc or a click elsewhere finishes. A box left empty is discarded.
- **Editing later:** double-click a text Annotation.
- **Styling:** one style per box (font, size, colour); no mixed styles inside one box.
- **Width:** dragging a selected text box's left or right handle sets a fixed width, and the text then wraps at that width.
- **Input:** input-method composition (for CJK and similar) must work.

### 4.5 Step counter

Step counters are numbered 1…n in the order they were created. Deleting one renumbers the rest; undoing the deletion restores the old numbering. Numbers can't be set by hand.

### 4.6 Insets

**Created by:**
- Ctrl+V with an image on the clipboard (§6.3);
- Ctrl+drop of an image file.

**Placement:** at 100%, centred in the view, and scaled down to fit inside the Image if it's larger.

**Resizing:** corner handles resize it with the aspect ratio locked; Shift unlocks it.

**Properties:** shadow and border only. Image operations treat an Inset like any other shape.

### 4.7 Image operations

Crop, rotate 90° (either way), flip (horizontal or vertical) and resize, from the Image menu, the quick action or the crop tool. **Annotations stay editable through all of them** ([ADR 0001](../adr/0001-annotations-survive-image-operations.md)):

| Operation | Effect on Annotations |
|---|---|
| Crop | Each Annotation keeps its position in the image. Those partly inside are clipped; those entirely outside are removed, and undoing the crop restores them |
| Rotate, flip | Shapes, lines, arrows, freehand strokes and Insets transform with the Image. Text and Step counters move to their new anchor but stay upright |
| Resize | Everything scales with the Image, including line thickness and font size |

**Resize dialog:** width and height in pixels or as a percentage, with the aspect ratio locked by default. Resampling is Skia's cubic (Mitchell) for upscaling and mipmap plus cubic for downscaling.

**Limit for editing:** editing needs the full-resolution decode, which starts with the first tool use or Image operation, or when you zoom past Fit. It's allowed up to **100 MP**. Larger images open **view-only**: the tools are disabled, and the status bar shows "View only: image too large to edit". There is no tiled rendering in v1.

### 4.8 History (undo and redo)

- **Shortcuts:** Ctrl+Z undoes; Ctrl+Shift+Z and Ctrl+Y redo.
- **One linear History** covers Annotation edits and Image operations alike. One gesture is one step:
  - a whole drag (draw, move or resize);
  - one property change;
  - one text-editing session (from opening the box to finishing it);
  - one Image operation;
  - one paste or one duplicate.
- **Image operation steps** store the pixels and the Annotation geometry from before the operation. Stored pixels are capped at about **512 MB**; beyond that, the oldest steps are dropped.
- **Saving** doesn't clear the History. Undoing after a save marks the Image as unsaved again.
- **Moving to another Sibling** (after save or discard) clears the History.

## 5. Formats and codecs

Decided in [Image codec libraries](https://github.com/acastaner/zimged/issues/3) and [Lock the stack](https://github.com/acastaner/zimged/issues/10).

### 5.1 Formats

| Format | Read | Write | Library |
|---|---|---|---|
| JPEG | ✅ | ✅ (quality setting, default 92) | `image` (zune-jpeg; jpeg-encoder) |
| PNG | ✅ | ✅ | `image` (png) |
| WebP | ✅ (incl. animated) | ✅ lossy and lossless | `image` (image-webp) to read; libwebp (`webp` crate) to write |
| GIF | ✅ (incl. animated) | — | `image` (gif) |
| BMP, ICO | ✅ | — | `image` |
| TIFF | ✅ | — | `image` (tiff) |
| AVIF | ✅ | — | libavif + dav1d |
| HEIC/HEIF | out of scope | — | — |

- **Ctrl+S** writes the Image back in its own format.
- **Ctrl+S on a read-only format** (GIF, BMP, ICO, TIFF, AVIF) acts as Save As, defaulting to PNG.
- **Save As** offers PNG, JPEG and WebP.
- **WebP compression:** WebP is written lossless when the source is lossless (PNG, GIF, BMP, ICO, TIFF, or lossless WebP), and lossy at quality 90 otherwise. There is no user choice.

### 5.2 Decoding

- **Display-size first:** every Image and every prefetch decodes for display. JPEG is decoded in full, then reduced with `fast_image_resize` to fit the window's physical pixel size, never above the original size.
- **Full resolution:** decoded on demand when editing starts (§4.7), in the background.
- **Possible later optimisation:** libjpeg-turbo DCT-scaled decoding (`turbojpeg`), adopted only if measurements show it's needed. It was the cheapest decode in the spike.
- **Orientation:** the EXIF orientation is applied at decode.
- **Colour:** an embedded ICC profile that isn't sRGB is converted to sRGB with **lcms2**. sRGB and untagged images skip the conversion. The display is assumed to be sRGB; there is no per-monitor colour management in v1.
- **Decode failure:** the canvas shows "Can't open <name>: <reason>". Navigation keeps working.

### 5.3 Saving

- **Output:** saving writes the Flattened image (§7.2).
- **EXIF:** kept where the format allows. Because orientation is baked into the pixels, the EXIF orientation tag (0x0112) is set to 1.
- **ICC:** the original profile is kept, unless the image was converted to sRGB on decode, in which case sRGB is written.
- **Safe write:** a temporary file in the same directory, then an atomic rename.
- **Writing an edited animation** over its own file needs confirmation (§6.4).

## 6. Saving, clipboard and dialogs

### 6.1 Keyboard

| Shortcut | Action |
|---|---|
| Ctrl+S | Save in place (Save As for a clipboard image or a read-only format) |
| Ctrl+Shift+S | Save As (native dialog) |
| Ctrl+O | Open |
| Ctrl+C | Copy (§6.2) |
| Ctrl+V | Paste (§6.3) |
| Ctrl+Shift+V | Open the clipboard image in a new window (also *File › New from clipboard*) |
| Ctrl+D | Duplicate the selected Annotations |
| Ctrl+Z / Ctrl+Shift+Z / Ctrl+Y | Undo / redo / redo |
| Ctrl+] / Ctrl+[ | Move the selection up / down one level |
| Delete | Delete the selected Annotations, or trash the file |
| F11 | Fullscreen |

On macOS, Cmd replaces Ctrl.

### 6.2 Copy

- **With Annotations selected:** copies them, publishing two formats together:
  - `application/x-zimged-annotations+json`: the serialised Annotations, with their styles and positions relative to the Image;
  - `image/png`: just those Annotations on a transparent background. Highlight and obfuscate are left out of it, since they mean nothing without the pixels underneath.

  The status bar says "Annotations copied to the clipboard".
- **With nothing selected:** copies the Flattened Image as `image/png`. The status bar says "Image copied to the clipboard".

### 6.3 Paste

- **Clipboard holds zimged Annotations:** they're added to the current Image and selected. If they'd land exactly on top of the originals, they're offset by 10 px. This works across Siblings and across zimged windows.
- **Clipboard holds an image:** it's inserted as an **Inset** (§4.6), even when a drawing tool is active or Annotations are selected. zimged switches to the select tool and selects the new Inset.
- **Clipboard holds anything else:** nothing happens, and the status bar says "Nothing to paste".

### 6.4 Dialogs

| When | Title / text | Buttons (primary in bold) |
|---|---|---|
| Moving to a Sibling, opening or dropping a file, or closing the window with unsaved changes | "Save changes?" / "<name> has unsaved changes." | Cancel · Discard · **Save** |
| Saving an edited animation over its own file | "Overwrite animated image?" / "Saving will replace the animated file <name> with a still image. All frames except the first will be lost." | Cancel · Save As… · **Overwrite** |
| Resize | Width and height (px or %), aspect-ratio lock | Cancel · **Resize** |

Esc means Cancel in every dialog.

## 7. Architecture

[ADR 0002](../adr/0002-rust-egui-glow-linux-first.md) chose Rust, eframe/egui on glow and Linux-first. [ADR 0003](../adr/0003-skia-single-annotation-renderer.md) chose Skia as the single Annotation renderer. [ADR 0004](../adr/0004-gpl-3-licence.md) chose the GPL-3.0-or-later licence.

### 7.1 Crates (one Cargo workspace)

| Crate | Responsibility | Depends on |
|---|---|---|
| `zimged` (bin) | Startup path (§1.3), the eframe app, egui chrome (menu, property bar, tool strip, status bar, dialogs), input → commands | all below |
| `zimged-core` | The domain, with no UI and no I/O: the Document (Image pixels, Annotations, Selection, History), Annotation types and their geometric transforms, Image operations, Step counter numbering, the clipboard JSON (serde) | — |
| `zimged-render` | Skia (`skia-safe`, CPU raster, `textlayout`): render a Document region at screen resolution, Flatten at full resolution, the effects (highlight, obfuscate, shadow), resampling | `zimged-core` |
| `zimged-codec` | Decode at display size and at full resolution, animation frames, EXIF orientation, lcms2 colour conversion, encoding, EXIF/ICC write-back, safe atomic save | — |
| `zimged-siblings` | Directory scan, per-platform ordering (§3.2), the `notify` watcher, prefetch scheduling and the cache (§3.3) | `zimged-codec` |
| `zimged-platform` | Clipboard (`clipboard-rs` on Windows/macOS/X11, `wl-clipboard-rs` on Wayland), trash (`trash`), dialogs (`rfd`), config dirs (`directories`), single instance (`interprocess`), config file (`serde` + `toml`) | — |

`zimged-core` is the deep module. Tests drive it through the headless App rather than directly (§9).

### 7.2 Rendering

- **No Annotations:** the display-size Image is a GL texture drawn by egui, fit and zoomed.
- **With Annotations:** `zimged-render` composites the visible region of the Image plus every Annotation with Skia, at the window's physical resolution, and uploads it as one texture. Re-rendering is limited to the dirty region where that's possible. egui draws the selection boxes and handles on top.
- **Zoomed in past the display-size decode:** this uses the full-resolution pixels, which are decoded on demand.
- **Flatten** (save or copy): renders the full-resolution Image plus every Annotation with the same Skia code, on a worker thread, so the screen and the file match.
- **Skia** is initialised on the first Annotation. Fonts are enumerated the first time the text tool is used.

### 7.3 Threads

| Thread | Work |
|---|---|
| UI (main) | winit/eframe event loop, egui, commands on `zimged-core`, on-screen Skia composite |
| First-image decode | Started at `main()` (§1.3) |
| Config | Reads `config.toml` at `main()`, and writes it (debounced) when it changes |
| Decode pool | `min(4, cores ÷ 2)` threads: prefetch and full-resolution decodes |
| Directory | Scan and `notify` watcher |
| Worker | Flatten for save and copy, encoding, atomic writes |
| Single-instance listener | Only when *Allow multiple instances* is off |

## 8. Platform integration

### 8.1 Clipboard

The [ADR 0002](../adr/0002-rust-egui-glow-linux-first.md) amendment covers this:

- **Crates:** `clipboard-rs` on Windows, macOS and X11; `wl-clipboard-rs` on Wayland.
- **Formats:** §6.2 and §6.3.
- **Wayland:** clipboard access needs a compositor with data-control (KWin, wlroots, recent GNOME). Without it, zimged falls back to XWayland's clipboard.

### 8.2 Trash and dialogs

- **Trash:** the `trash` crate (freedesktop Trash spec on Linux, the Recycle Bin, the macOS Trash).
- **Dialogs:** `rfd`, using the XDG desktop portal on Linux.

### 8.3 Configuration

- **Location:** `config.toml` in the OS's user-config directory, resolved with `directories`:
  - Linux: `$XDG_CONFIG_HOME/zimged/`, defaulting to `~/.config/zimged/`;
  - Windows: `%APPDATA%\zimged\`;
  - macOS: `~/Library/Application Support/zimged/`.
- **Format:** TOML with `version = 1` first. Unknown keys are ignored and missing keys take their defaults.
- **Corrupt file:** renamed to `config.toml.bad`, and zimged starts with defaults.
- **Writes:** atomic, and debounced.

| Key | Default |
|---|---|
| `allow_multiple_instances` | `true` |
| `jpeg_quality` | `92` |
| `window` (width, height, maximised) | 1600×1000, not maximised |
| `tools.<tool>` (each tool's last style, §4.3) | Greenshot-like defaults: red, 3 px, shadow on |
| `magnify_factor` | `2` |

There is no preferences dialog in v1. *Allow multiple instances* is a toggle in the View menu.

### 8.4 Instances

- **Allow multiple instances on (the default):** every open is its own process and window.
- **Allow multiple instances off:**
  - At startup, zimged connects to a local socket (`interprocess`: a Unix socket in `$XDG_RUNTIME_DIR` on Linux, a named pipe on Windows) and sends the path.
  - If a running instance answers, the new process exits. The running window raises itself and opens the path, with the unsaved-changes prompt if needed.
  - If nothing answers, this process becomes the listener.

### 8.5 Packaging and file associations

| Platform | Artifacts | Associations |
|---|---|---|
| Linux (primary) | `.deb` (`cargo-deb`), `.rpm` (`cargo-generate-rpm`), AUR `PKGBUILD`, tarball | `zimged.desktop` with `MimeType=` covering every readable format, plus an icon |
| Linux (secondary) | Flatpak (not budgeted, §1.2) | the same `.desktop` |
| Windows | MSI (`cargo-wix`) and winget manifest | ProgIDs and *Open with* entries for every readable extension |
| macOS | `.app` in a DMG, ad-hoc signed | `CFBundleDocumentTypes` in Info.plist |

zimged registers as **a** handler but never makes itself the default; the user chooses.

### 8.6 Accessibility

- **Keyboard:** everything is reachable from the keyboard. There are tool shortcuts, and Tab and the arrow keys move through the menus and property-bar controls.
- **Screen readers:** egui's AccessKit integration labels the menus, tools and controls.
- **Canvas:** Annotations on the canvas aren't announced to screen readers in v1.

## 9. Testing and the gate

The gate is a port of the clean-room local gate (`~/scripts/agent-memory/hosts/clavain/clean-room-local-gate.md`; the reference implementation is `~/Git/dotnet-forgeLog/tools/local-ci/`).

- **Script:** `tools/local-ci/run.sh` runs the gate in a container, on a fresh clone of the committed HEAD. It refuses to run with a dirty tree.
- **Image:** the gate image pins the Rust version read from `rust-toolchain.toml`, with a preflight that fails on a mismatch.
- **Suites:**
  - `lint`: `cargo fmt --check` and `cargo clippy --workspace --all-targets --all-features -- -D warnings`.
  - `test`: `cargo test --workspace --all-features`. Both run with `--all-features`, so the opt-in `avif` feature (§5.1) is checked. Tests go through **three seams** only; the crates of §7.1 structure the code but aren't test seams of their own:
    - **The headless App (primary).** The real `zimged` app, run without a window under `egui_kittest`. Tests send user input (open a path, keys, drags on the canvas, drops) and assert on what the user sees: status-bar text and messages (found by their accessibility labels), the open dialog, the Document's Annotations and History, and the canvas and Flatten pixels compared within a tolerance against golden PNGs in `tests/golden/`. Clipboard, trash, file dialogs and the config directory sit behind adapter traits with in-memory fakes. Fixture images in `tests/fixtures/` are copied into a temporary directory, so decode, save, EXIF/ICC round-trips and Sibling scans run for real. This seam covers History steps and caps, Annotation transforms under Image operations, Step counter renumbering, selection, copy and paste in both formats, the unsaved-changes flow, every tool and mode, Flatten matching the screen, the view-only limit, codecs, and config defaults and corrupt-file handling.
    - **The Sibling ordering comparator.** A pure `compare(a, b)` per ordering rule (the GLib and Dolphin ports), tested against tables of name pairs, including the documented quirks. These take dozens of cases each, too many to build as directories through the App.
    - **Platform adapters against the real OS service.** Where the App's tests use an adapter's in-memory fake, the real adapter may be tested on its own against the service it wraps, when the gate's container provides it: for example the single-instance socket (§8.4) between two listeners in a temporary directory. These tests check that the fake's contract holds for the real thing.
- **Record:** a clean-room pass of all suites writes `git notes --ref=gate` on the commit's **tree** and pushes `refs/notes/gate`.
- **Release:** `.github/workflows/release.yml` starts with a `gate-record` job that refuses an ungated tree. It then builds the artifacts of §8.5 for Linux, Windows and macOS. GitHub runs no tests.
- **Performance:** `tools/bench`, descended from the spike's `bench.py`, measures §1.2. It is **not** part of the gate, because it depends on hardware and the power profile. It's run by hand on the reference machine before each release, and its numbers go in the release notes.

## 10. Suggested implementation order

This order is for cutting implementation tickets; it isn't binding.

1. **Walking skeleton:** the workspace, `rust-toolchain.toml`, the startup path (§1.3), display-size JPEG decode, fit and zoom, the Sibling scan with the Linux ordering, prefetch, the status bar, and `tools/bench`. Check §1.2 on the reference machine **before** building further.
2. **Clean-room gate:** port the gate (§9) as soon as there's something to test.
3. **Viewer complete:** all formats, animation, EXIF orientation and colour conversion, the `notify` watcher, trash, the empty window, open, drop, F11, and config.
4. **Editor core:** the `zimged-core` Document, Annotations, Selection and History, the Skia renderer, select, rectangle, ellipse, line, arrow and freehand, plus the property bar.
5. **Editor complete:** text, Step counter, highlight and obfuscate, Insets, and the drawing aids.
6. **Image operations:** crop, rotate, flip and resize, with the Annotation transforms and the view-only limit.
7. **Output:** Flatten, save and save-as with EXIF/ICC, the animation-overwrite prompt, the clipboard (both formats, all platforms), and the unsaved-changes flow.
8. **Platform:** single instance, accessibility labels, and packaging and associations (§8.5), with the release workflow.

## 11. Out of scope for v1

- Screenshot capture (possibly a future effort).
- Greenshot's `.greenshot` editable project format, and any other way to keep Annotations after saving.
- Greenshot's Effects group (drop shadow, torn edges, border, grayscale, invert), speech bubbles and auto-crop.
- Thumbnail strip, and view-only rotation (rotation is an Image operation).
- HEIC/HEIF.
- Per-monitor colour management.
- Tiled rendering, and editing images over 100 MP.
- A preferences dialog.
- Translations: UI strings are kept in one table, but only English ships.
- Performance budgets on Windows and macOS, and on the Flatpak build.
