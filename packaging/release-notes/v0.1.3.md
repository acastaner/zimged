A maintenance release: internal restructuring only, with no change to how zimged behaves.

## Internal

- The large `app` module was split into its own directory, with the save and copy flows moved into
  dedicated modules and state that travels together grouped into types.
- Each tool's data (name, shortcut, config key, properties, constructor) now lives in one
  descriptor table, so adding a tool is a single entry.
- The save and copy worker jobs share one input type, and flattening reports a typed error instead
  of a bare string.

No user-facing behaviour changed; the full headless test suite passes unchanged.
